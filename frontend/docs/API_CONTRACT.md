# AKI NATOR frontend API contract · v1

The authoritative TypeScript shapes are in `src/lib/types.ts`. This is a proposed integration contract, not a claim that a separately developed backend already implements these routes. All endpoint paths append to `VITE_API_BASE_URL` (which may include `/api/v1`). All data requests send a bearer token. CORS must allow the configured frontend origin, Authorization and Content-Type.

| Method / route              | Request                 | JSON response                                                          |
| --------------------------- | ----------------------- | ---------------------------------------------------------------------- |
| GET /health                 | None                    | `{ "status": "ok", "service": "aki-nator" }`                           |
| POST /auth/login            | `{email,password}`      | `Session`                                                              |
| POST /auth/register         | `{name,email,password}` | `Session`, default role Doctor                                         |
| GET /patients               | Bearer token            | `Patient[]`, including readings and forecasts                          |
| GET /models/status          | Bearer token            | `ModelStatus`                                                          |
| GET /analytics/evaluations  | Researcher/Admin token  | `Evaluation[]`; empty array if unavailable                             |
| POST /patients/:id/readings | `{readings: Reading[]}` | Updated `Patient` with forecasts invalidated or regenerated by backend |

The client currently loads a small cohort including histories. For production scale, replace `api.load` with paginated summaries and on-demand histories; keep the same component-level types. Backend authorization must not rely on frontend route guards. Registration must never accept a privileged role chosen by the client.

Session: `{ user: {id,name,email,role}, token, mode: "backend" }`. Role is `doctor`, `researcher` or `admin`. Use HTTPS and server-managed sessions/secure cookies for a production deployment. The prototype bearer token lives only in sessionStorage.

Patients use de-identified ICU stay IDs and contain `age`, `sex` (`Female`, `Male`, `Unknown`), `source` (`MIMIC-IV`, `eICU-CRD`, `CSV`, `Manual`), `unit`, `admission`, `admittedAt`, `durationHours`, optional `weightKg`, `esrd`, `chronicDialysis`, optional `rrtAt`, `readings`, `forecasts`, and `synthetic`. Booleans must be explicit. Include pre-admission creatinine history if it is legitimately available to the model; the UI accepts backend histories but local imports are constrained to the stay.

Recorded ICU outcome:

Optional `Patient.outcome` supplies a recorded terminal ICU outcome:

```json
{ "status": "died", "at": "2025-02-17T06:00:00.000Z", "availableAt": "2025-02-17T08:00:00.000Z" }
```

Status is `died` or `discharged_alive`. Omit unknown outcomes. The event must lie within the stay, not precede recorded measurements, and become available no earlier than occurrence. The frontend canonicalizes these times, excludes future/unavailable outcomes, and computes a descriptive deaths/known-completed-stays percentage. Unknown/ongoing outcomes do not enter the denominator. Cohort curves align by elapsed ICU hours; this is not predicted mortality or AKI-attributable mortality. No additional endpoint is required. After a terminal outcome is available, the UI suppresses further new ICU forecasts. Outcome labels never enter the prediction feature set. Local outcome entry/CSV import is available only for fictional stays in synthetic mode.

Reading:

```json
{
  "id": "r1",
  "at": "2025-02-14T12:00:00.000Z",
  "availableAt": "2025-02-14T12:30:00.000Z",
  "key": "creatinine",
  "value": 1.1
}
```

`at` is observation/collection time, `availableAt` is the earliest time the result was available. Use canonical UTC ISO 8601 strings and chronological arrays. Do not send invalid numbers or imply that a missing measurement is zero. Urine observations are normalized mL/kg/h averages for a **complete, non-overlapping collection interval ending at `at`**, with `intervalHours` and the patient's weight recorded.

| Measurement                     | Canonical unit |
| ------------------------------- | -------------- |
| creatinine, bun                 | mg/dL          |
| urineOutput                     | mL/kg/h        |
| map                             | mmHg           |
| heartRate                       | bpm            |
| spo2                            | %              |
| potassium, bicarbonate, lactate | mmol/L         |

Forecast:

```json
{
  "at": "2025-02-14T18:00:00.000Z",
  "availableAt": "2025-02-14T18:01:00.000Z",
  "probability": 0.27,
  "horizonHours": 24,
  "synthetic": false,
  "modelVersion": "frozen-model-id",
  "contributions": [
    { "feature": "creatinine_slope_12h", "value": 0.04, "method": "Backend-provided contribution method" }
  ]
}
```

Only return real predictions for eligible stays, built exclusively from information available at the prediction time. The frontend additionally hides ineligible/stale forecasts. Do not compute predictions in the browser from a heuristic and present them as a trained model. SHAP labeling is acceptable only when the backend actually supplies SHAP values and method metadata. Future outcome labels must never be forecast input.

ModelStatus: `{state: "unavailable" | "ready", version?: string, description: string}`. Return unavailable when no model exists.

Evaluation: `{id,name,trainSource,testSource,cohortSize,metrics,roc?,precisionRecall?,calibration?,falseAlertsPerPatientDay?,medianLeadTimeHours?}`. `metrics` is `[{name,value,lower?,upper?}]`, using `AUROC`, `AUPRC`, `Brier score` for the summary cards. Curves are `{x,y}[]` on [0,1]. Omit unavailable results; do not return zero as a placeholder. Evaluation cohort size must refer to the held-out cohort. Frontend loaded counts are never substituted for evaluation counts. Lower/upper must identify a documented confidence interval.

Errors: return appropriate HTTP status with `{ "detail": "Human-readable message" }`. The UI handles non-JSON errors, offline connections and timeout. The current client treats missing required cohort/model/evaluation endpoints as an integration error and offers explicit fallback; partial-data support can be added centrally when the backend contract requires it.

**Research prototype only.** Dataset credentialing, unit harmonization, clinically adjudicated labels, cohort eligibility, leakage review, model validation and all authorization remain backend/research-team responsibilities. Do not send restricted records to third-party AI services.
